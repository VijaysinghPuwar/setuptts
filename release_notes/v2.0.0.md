## SetupTTS v2.0.0

**Online audiobooks are several times faster, and both Microsoft endpoints work again.**

---

### Faster

- **Several sections at once.** A book is sent to Microsoft in sections. Until now SetupTTS waited for each one to finish before asking for the next, and the connection sat idle most of the time. Now up to three sections stream at the same time. On the live service, six 8,600-character sections took 128 seconds one at a time and 18 seconds three at a time. A 3.3-hour audiobook (169,000 characters of *Moby-Dick*) was finished and verified in under 9 minutes.
- **Same safety checks.** Sections are still saved strictly in order. Resume, the check that every character of the text is covered, and the audio-length check all work exactly as before.
- **Gentle with the service.** The first section runs on its own as a warm-up. After any failed attempt, the job goes back to one section at a time for two minutes. If Microsoft answers "too many requests", the job keeps to fewer sections for the rest of its run.

### Fixed

- **Backup endpoint restored.** Microsoft began refusing the older sign-in token on `speech.platform.bing.com`, so the backup endpoint SetupTTS switches to when the main one refuses was not working. SetupTTS now uses edge-tts 7.3.1, which sends the new token, and both endpoints work.
- **Endpoint refusals.** A refusal is recognised even when it arrives wrapped in a clock-correction error. Previews now switch endpoints too.
- **Volume for offline and built-in voices.** The Volume setting now changes offline (Piper) and Windows/macOS voices. Before, it only affected online voices.
- **Sections are not cut after abbreviations.** A section no longer ends between "Dr." and "Smith", or after "e.g." or an initial. Hindi, Bengali, Urdu, Arabic, Burmese, Amharic and Khmer sentence endings are recognised.
- **Saved audio is never thrown away by mistake.** An older "(incomplete)" copy of the same name no longer makes a job delete its own saved sections.
- **Disk-space checks.** A finished book is no longer reported as failed when the disk fills just after it is saved. A job stopped by a full disk can be resumed once space is freed.
- **Quitting the app.** Closing during a job, a voice-list load or a voice download no longer freezes the window or crashes the app on exit.
- **Saved preferences survive.** Saved language and source filters are no longer reset at launch. Typing in the voice search no longer changes your saved voice. A maximised window reopens maximised.
- **Opening files.**
  - A UTF-8 file with one damaged byte is no longer garbled throughout.
  - A file with a stray zero byte is no longer read as UTF-16.
  - UTF-16 Thai, Lao and Khmer files without a byte-order mark open correctly.
  - Dropping a Word or PDF file no longer pastes its path into the text.
- **Offline voices.**
  - Text in `[[double brackets]]` is read normally.
  - Very high speeds no longer garble words.
  - A system voice that crashes is restarted once.
  - Leftover temporary files and half-finished voice downloads are cleaned up.
- **Status messages.** Resuming a job that is already running shows a clear message instead of quietly starting over. The status line follows the section the job is waiting on and no longer jumps between sections.

### Tested

- **Automated tests.** 870 automated tests, including new ones for every fix above. The parallel tests use a fake service that answers later sections first, to prove the audio still comes out in order.
- **Live tests.**
  - A 3.3-hour book went through the real service; one "too many requests" reply was handled on the way.
  - The app's self-test passed: online, offline and Windows voices all spoke.
