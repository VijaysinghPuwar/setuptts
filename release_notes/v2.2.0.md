## SetupTTS v2.2.0

**Audiobook compression: the same narration in up to half the disk space.**

---

### New

- **Audiobook compression, on by default.** Spoken word doesn't need the voices' native bitrate, so saved MP3 files are now made smaller automatically. **Settings ▸ Audiobook compression** offers three levels, or **Off**:

  | Level | Bitrate | Per hour of audio | Online voices | Offline voices |
  |---|---|---|---|---|
  | Light | 40 kbit/s | ~18 MB | 17% smaller | 38% smaller |
  | **Balanced** (default) | 32 kbit/s | ~14 MB | 33% smaller | 50% smaller |
  | Smallest | 24 kbit/s | ~11 MB | 50% smaller | 63% smaller |

  A 10-hour book with an offline voice drops from about 290 MB to about 145 MB at **Balanced**.
- **You can always see it.** The Export card shows the level new files will use, with a **Change** link that opens Settings.
- **Offline voices** (Kokoro HD, Piper, built-in) are encoded straight at the chosen bitrate, so this costs no extra time.
- **Online voices** arrive from the service at 48 kbit/s. The finished file is re-encoded after its coverage has been verified, and the job card shows **Compressing… N%**. A 12-hour book takes about 4–6 minutes.

### Your audio is never at risk

- The smaller copy is written next to the original and checked first. It must decode to the same length (within a second) and actually be smaller. Only then does it replace the original.
- If anything goes wrong (an unreadable file, a full disk, the file open in a player), the full-quality file is kept and the job still completes.
- Cancelling during compression keeps the complete, uncompressed book.

### Fixes

- **"QFont::setPointSize: Point size <= 0 (-1)" in the log (Windows).** It appeared in about one session in four, the first time a drop-down list was opened. Qt's Windows 11 style copies a font's point size, and the app's pixel-sized fonts don't have one. Font sizes are now given to Qt in the identical point size on Windows. Screenshots of the main window, Settings and the drop-down before and after match pixel for pixel.
- **Settings ▸ About** no longer says an internet connection is always required. Offline voices run entirely on your computer.
- The free disk space check for offline voices now accounts for compression, so a nearly full disk isn't refused for a file that would fit.

### Tested

- **Real voices, end to end.** A real online voice (Andrew) and a real Windows built-in voice were run through the app's own job workers (online: Off, Balanced, Smallest; built-in: Off, Balanced). The files came out at exactly 48 / 32 / 24 kbit/s (online) and 64 / 32 kbit/s (built-in), with the same length. A live "too many requests" response from the service during the run was retried normally.
- **It still sounds the same.** Real online speech was compressed at each level and compared with the original waveform. Correlation was 0.995 (Light), 0.994 (Balanced) and 0.992 (Smallest).
- **On real audiobooks.** A 50-minute book the app had made shrank from 17.9 MB to 14.9 / 11.9 / 9.0 MB. Every level kept its length to within 0.07 s (encoder padding). Compression ran at 120–180× realtime.
- **Failure paths.** Unreadable input, a locked file, a cancel midway and a length mismatch each leave the original byte-for-byte unchanged, with no temporary file left behind. Tests were also checked against deliberately broken code to confirm they catch real faults.
- **The packaged apps.** A new `compression` self-test check runs inside every built app (DMG, zip, installer, portable), so a missing decoder fails the build instead of reaching you.
- 28 new automated tests.
